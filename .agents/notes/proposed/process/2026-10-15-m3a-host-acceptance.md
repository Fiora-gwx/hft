# Agent Note: M3-lite 主机验收边界

Status: proposed

## Problem

冻结的主机与部署用例同时要求真实 sim/advisor、升级主机线程表、检查点恢复、完整冷进程和发布基础设施。当前可执行装配只有新 journal 会话、NoModel、dev2 prod/testnet；将替身断言或静态生成物计为完整主机验收会掩盖运行缺口。

## Decision

提请负责人按实际运行依赖复核分类，保持现有里程碑与冻结矩阵不动。dev2 生成与安装工具只接受自身支持的角色集合；未知主机或未装配组失败。完整验收以组件 TESTS 的覆盖边界为准，不以 test-trace 找到函数名为准。

需要真实主机或特权系统环境的 CPU 让出、OOM 顺序、I/O 限速、ENI/EIP、aarch64 特性、IAM 与服务权限闭包保留为未验收。普通 CI 容器只承担文件属主、降权、原子文件行为和可替换命令边界的验证。

需要先接通发布工作流的输入包括 staging、完整 RELEASE 元数据、SBOM 与带哈希的离线 Python 依赖闭包。hft-secrets 的调用使用 tools 实现；IMDS 未加载或缺失实际秘密清单时预检失败，不能将安装工具通过解释为测试网可启动。

场景 C15 的 FundingStats 与当前 NoModel 装配不同，需要模型/统计基础；W1 的完整主机/角色矩阵不能由当前单子集代表。C12 中 OKX/Meta Notes 不属于本次双交易所测试网范围。这些分类由负责人决定，本改动不改场景或里程碑。

## Alternatives considered

- 给冻结用例加空测试或只检查配置文本会制造不真实的验收计数。
- 放宽主机预检或把缺失的安全进程替换为空命令会允许不完整装配启动。
- 同时扩建全部 sim、advisor、恢复和冷进程会越过当前并行模块分工，也不构成可独立审阅的部署改动。

## Consequences

当前工具提供可测试的安装与冷激活机制，并在不完整主机上失败关闭。完整发布与主机验收仍需后续实现和真实环境证据；正式上线门槛不变。
