# Agent Note: M3-lite 两所两策略测试网范围提案

Status: proposed

## Problem

M3 自动用例清单有 789 条未实现。它同时包含真实交易主路径、正式主机与运维、未使用的深度功能和检查器重复矩阵，按整个里程碑推进会推迟两策略的真实联调。[M2-lite](../../implemented/architecture/2026-10-14-m2-lite.md)已采用按资金主路径收窄范围的做法。

本提案以 `ef185743` 合入五个 M3 区域 PR 后的规格为基线。输入为负责人提供的 `M3-after.md` 及同目录 `m3-after.json`。Markdown 正文只列 678 条；其生成器漏扫根级 `deploy/TESTS.md` 的 91 条及 `tools/TESTS.md` 的 20 条。JSON 的 789 个编号在本基线均能定位为 M3，以下逐项覆盖，计数没有用“推迟”冒充“完成”。原始 JSON 的 SHA-256 为 `28955a0750d4f719c34b785491654fe22c1567b15bf82db38ed1d1d85a29b111`。

## Proposal

**待负责人批准；本草稿只调整验收排期，不修改运行代码、资金/风控/恢复语义，不授权部署或交易。** 保留已实现用例的里程碑、用例正文、实现字段与当前里程碑配置。类别只表达对本次目标的必要性，不表示实现状态。

- **A → M3**，477 条：Binance + Bitget 的订单、成交、仓位、余额、实际资金费、账户与启动闸门、限速、连接重建、Kill/Drain、dev2 共机安全和延迟关键路径。
- **B → M5/M6/M7**，136 条：正式资金上线前仍须完成。按[既有里程碑含义](../../../../design/11-实施路线图.md#3-里程碑按依赖)，M5 为恢复/运维/发布（66 条），M6 为联调/验证长跑（15 条），M7 为选定生产主机与隔离/容量/延迟验收（55 条）。
- **C → M9**，176 条：当前不启用的功能或已有直接覆盖的扩展矩阵。它们保留编号与冻结期望，启用对应能力前重新排期；M9 不表示可以带已知交易错误上线。

目标策略为 [cross-taker](../../../../strategies/cross-taker/README.md) 和 [portfolio-carry](../../../../strategies/portfolio-carry/README.md)，均为 NoModel、同事件双 IOC，当前只需要 BBO/mark/funding 等已声明输入。现货与 USDT 永续的账户/订单基本支持保留 A，不另外裁掉现货；第一轮实测可选两所永续组合，报告必须写明实际测到的市场，不能推广成未跑过的现货验收。

**一个 venue 一个账户、一个账户一个策略实例。** 两策略顺序运行；换策略前停止开仓、撤空、平仓、完成最终对账，下一轮使用新 journal 和已核验基线。不得为同时跑两策略绕过账户独占或启用同所多账户。跨两个 venue 的两个账户隔离仍是 A（如 CORE-031/313），只有同一 venue 多账户 CORE-330 属于 C。

两所保持当前资金费来源：预测费率用于决策，实际入账使用认证历史账单（FundingHistoryProtocol/FundingPoll）；Binance 的可选 BalanceOnlyPush 路径 BIN-113–116 归 C。不得因这四例推迟而省掉实际结算、去重和期初水位验证。Bitget 晚到费用 BGT-107/321 排 M6 是待事实核实的接口分支；M3 核账若出现费用缺失，必须修复后重新验收，不能延后真实缺陷。

深度订阅/全量重同步、批量下单、buffered TLS、空闲预热、refdata 热替换与 advisor 不启用。当前 unbuffered TLS、单品种 BBO 补帧、单单 IOC、文件配置重启路径保留。混合用例中只要包含主路径必要行为就整例留 A（如 BIN-326 同含 Spot 查询与改单），不改写期望凑数。正常输入与典型反例仍须通过；C 中的“重复”仅指额外的检查器变异矩阵，不豁免其被检查的规则。

## Acceptance criteria

### M3-lite 工程退出条件

1. A 的行为全部实现并通过核心测试；保留现有 deps/hot-check/doc-check/黄金输入检查和两策略真实引擎故障/确定性回放验证。test-trace 只报告缺口，不靠补空函数、修改实现字段或重生成 DST HashTrail 达成“零缺口”。同一候选 SHA 的 PR fast lane 所有实际执行门与 acceptance 成功。人工项必须附证据，CI 绿不等于 M3-lite 验收。
2. 冷启动先撤空遗留挂单、核验身份/模式/权限/杠杆、读取并记录余额和持仓基线，未满足闸门不新开仓。正式端点/正式 key 不进入 dev2。进程内的公共/私有 WS 重连、超时 Unknown、查询收敛和去重正常；不把传输失败当拒单，不用余额差异覆盖账本。
3. 当前 hft-core 对既有 journal 返回 RecoveryRequired，保留此失败关闭行为。M5 生产恢复尚未验收时，进程崩溃结束本轮；先人工查单、撤单、核账和平仓，再开启新会话。不得删除旧 journal 后直接接管未知仓位。独立撤单通路对两所可用；Bitget 不能假设有已开通的交易所死手。Kill/Drain 必须验证停止开仓、撤挂单、继续必要风险递减处置，不能留下未确认活动单或无界裸腿。
4. dev2 的内存、swap、CPU、I/O 与联调窗口护栏必须先有实测证据，不因本次裁剪影响旧系统。现有资源约束放不下时停止，另请负责人选已允许的退路；不以关闭护栏完成长跑。
5. 延迟先测再优化：候选制品先取得两所完整 feed → sequencer → gw 及回报路径直方图，分段仅用 latency-budget 的 kernel_rx、ingest、feed_host、decide、egress、tick_to_trade、rep_to_order、hedge_host。记录 p50/p99/p99.9、样本数、缺戳/校准过滤、负载、SHA 与主机配置；热路径零分配、无锁/阻塞与 BBO 等待上界仍为 A。dev2 只报告；参考机基准按现行预算比较，不能用 CI 或 dev2 数值宣称生产硬线通过。完整满订阅/双实例选档探针排到 M7 选机之前，单所或简化主循环结果不能代替最终探针。

### 真实测试网接受运行（拟定 N = 24 小时 / 策略）

连续执行两轮，每轮一个策略、两家真实测试网/模拟盘，**每轮至少连续 24 小时**，总计至少 48 小时策略运行。同一候选 SHA、固定并归档的参数与 refdata、真实 TLS/WS/REST、测试网行情和测试网订单；不得以 mock、dry-run、latency-probe 或主网行情混用替代。运行定义是待批的验收计划，本 PR 没有执行或授权该运行。

- 每轮至少记录 10 次真实双腿成交尝试及一次完整入场到平仓流程；两所均有 Place/Ack、实际 Fill、撤单或 IOC 终态与查单证据。cross-taker 若无符合冻结参数规则的机会则延长窗口并报告，不放松限额或伪造行情强迫成交；不能仅靠计时宣称通过。现货卖出必须来自合法分配库存，不能用期初未分配资产绕开归属。
- portfolio-carry 必须在两所都有永续持仓跨过至少一个各自真实资金费结算点，拿到认证账单；记录账单延迟、水位、正负号、去重与估算转实际差额。未发生结算则延长，模拟盘不提供账单或 UTA 下单能力不足则记为阻塞，交负责人裁决；零金额账单可验证通路，但不能代替非零金额入账证据。现货/永续组合的现货腿不要求资金费。
- 每轮在受控联调窗口至少对每所分别断开一次公共 BBO 和私有用户流，验证停新开仓、重连后补帧/查单/账单补查、重复回报不重记；合法限速退避不循环猛发，真实 429/超时若发生必须收敛。服务器错误/不易触发的拒单由已有故障注入补充，不通过制造交易所封禁取证。人工故障动作只能作用于 hft 测试网连接，不能扰动旧系统。
- 两轮各做一次非 HARD Kill 与一次 Drain。断连、Kill、Drain 的订单、链接和仓位收敛遵守已有配置时限；不新设更宽容差。计时窗口内发生进程崩溃、部署/参数变更或不变量破坏则失败，修复后该策略从零重新计满 24 小时。计划的连接故障属于运行负载，进程必须持续健康。
- **零不变量破坏**：已成交数量/现金/费用/资金费不重复或漏记；仓位只由成交/交易所证据改变；Unknown 不当失败；两腿 lot 对齐、风险限额/保证金/裸腿上界成立；Kill 后无非法开仓；每个可见决策已有 journal。全程监测，结束时不能只检查最终余额掩盖中途违规。
- 开始、每个结算点、故障收敛后及结束均做认证查询对账；结束先停止交易并撤空，在现有静默/无在途规则满足后取**连续两轮干净对账**。开放订单逐 ID 一致且最终为空、净仓最终为零（仅允许既有明确定义的 dust）、余额/手续费/资金费按资产定点及既有容差一致；所有差异解释并留原始脱敏证据，不能自动改账消差。若 reconciler 尚未可执行，用独立只读查询与 journal 离线复算形成同等证据，不能声称完整 M5 reconciler 已完成。
- 验收包包含发布 SHA/摘要、两所端点与能力核验结论、账户匿名映射、策略配置哈希、UTC 起止、交易及结算证据、脱敏 raw/seq journal、无不变量破坏报告、两轮最终对账和延迟直方图。密钥、签名原文、登录帧不入仓库或 journal。完整 journal 通过现有 verify；延期的逐字节恢复专用矩阵不用于豁免当前确定性失败。

### 正式资金上线仍被阻断的条件

B 全部完成才可进入正式资金上线，且不替代既有 M4 压力验收、M6 模拟账户至少 14 天、M7 同机隔离/满规模复跑/延迟门、累计 fuzz/DST、M8 零成交冒烟与 Shadow。其数值以路线图、[testing](../../../../docs/testing.md#8-上线门槛)与 [launch](../../../../docs/runbooks/launch.md) 为准，本提案不降门槛。M2-lite 把引擎内 Sim 排 M9 而既有上线门仍要求模拟长跑的张力已存在，负责人须单独明确交付依赖；不能以 48 小时测试网替代模拟门。两策略应分别取得其适用的上线证据。

## Alternatives considered

**继续按完整 M3 推进。** 输入清单中的三所/深度/主机全矩阵与实际两策略使用路径不一致；仅按总数推进不能尽早获得真实订单与资金费证据。

**所有非主路径都移 M9。** M2-lite 已否决这种处理：生产恢复、发布回滚和主机隔离仍是上线前依赖。本提案将它们按职责移到 M5/M6/M7，不把正式资金必要项推到上线后。

**只保留挂撤单冒烟。** 不能覆盖双 IOC 不对称成交、Unknown、真实资金费与最终账实一致，所以仍保留较多 A，用真实双策略运行作退出标准，不追求任意的较小用例数。

## Risks

负责人需批准：A/B/C 的排期、N=24 小时和每轮 10 次成交的可执行性、首轮产品组合及顺序运行安排、完整选档探针移至 M7。真实端点/UTA 账户/API 权限/非零资金费账单可用性仍待实测，缺失时保持阻塞，不默认 REST 替代 WS 或更改资金费来源。测试网结果不能证明主网流动性与撮合延迟。

C 的重复矩阵保留编号，生产行为缺陷仍必须立即修；BGT-068/105 在旧规格中已撤销但字段仍齐全，因此追踪器仍把它们计入未实现，本次只移 M9，不“复活”它们。BGT-303/304 的 books15 等历史用词也不在本次改语义。账户/资金的既有待评审变更见 [changes.md](../../../../docs/changes.md)，本提案没有追加资金或风控语义变更。
