# Agent Note: 主机类增加 c32 作为 prod + sim 同机的默认候选

Status: proposed

> **第八轮第五次修订(2026-10-03)**:收窄第 3 条——档位按 M3 末满订阅探针选定,`c16` 只在探针达标且启用 `epoll_pwait(0)` 时保留为候选,默认 `c32`;`c32` 线程计划预留核 28 给第二 IRQ 核(ENI-B2,默认不启用)。见 [m3-end-probe](2026-10-03-m3-end-probe.md)、[irq-split-reserve](2026-10-03-irq-split-reserve.md);依据 [round8e 简报](../../../../design/_work/round8e-spec-brief.md) E3、E4。

## Problem

收包改为中断驱动后需要一个不放线程的 IRQ 专用核([rx-irq-driven](2026-10-03-rx-irq-driven.md));feed 线程要拆成只承载 BBO 的 `feed-bbo` 与承载深度/成交/标记价的 `feed-md`,REST 快照移到 warm 任务([feed-split-and-snap-fetch](2026-10-03-feed-split-and-snap-fetch.md));persist 与段预创建要离开核 0;六个下单产品线各要一个独占的 gw 核;sim 还要自己的核与 ENI-C 的 IRQ 核。按这些原则,`c16`(16 vCPU)放不下首批全部 6 个下单产品线([V5 评审](../../../../design/_work/review-2026-10-03-M0c-V5延迟与整体.md) P1-3、§5-5)。

## Proposal

用户决定按推荐执行:按 M1.5 实测选档,宁可上更大档位,不砍首批 venue([round8-decisions](../../../../design/_work/round8-decisions.md) R8-10;[round8d 简报](../../../../design/_work/round8d-spec-brief.md) D4)。线程计划与内存表唯一归属 [hft-core](../../../../apps/hft-core/README.md#线程计划),主机清单与生成物归 [deploy](../../../../deploy/README.md#主机清单)。

1. 主机类枚举追加 `c32` = `c8g.8xlarge`(32 vCPU、64 GiB),作为 prod + sim 同机的**默认候选**;`HostClass` 编码只追加 `C32`。
2. `c16` 改为下限候选:首批下单 venue ≤ 4 时可用;`c8` 只能承载 prod(没有 sim),不能作统一升级主机。
3. 最终档位按 M1.5 实测在 M3 结束前选定([latency-probe-milestone](2026-10-03-latency-probe-milestone.md))。

## Alternatives considered

**留在 c16,限定首批下单 venue 数。** 省一半实例费用,但会砍掉首批策略需要的产品线;用户的取舍是延迟与覆盖优先。

**c16 上合并线程(BBO 与深度同线程、多 gw 同线程)。** 回到队头阻塞与 gw 不独占的问题,违反 T8 与 feed 拆分的初衷。

**prod 与 sim 分两台主机。** 用户此前决定同机([sim-colocated-with-prod](2026-10-03-sim-colocated-with-prod.md));两台主机的总费用与运维不低于一台 c32。

## Acceptance criteria

- hft-core 给出 c32 与 c16 的完整线程表、隔离集合、内存表与 slice 取值,deploy 生成器对两档都无错误。
- 选定档位上门槛 ⑩ 7 天通过,且同机干扰在 testing ⑩ 的判据内。
- 选档结论(M1.5 数据、核数与内存余量)记入 ops-log 与 architecture-v2/11。

## Risks

- c32 的按需费用约为 c16 的两倍;预算口径归 architecture-v2/11 §8。
- Graviton 实例的 ENA 队列数随规格变化;IRQ 专用核能否承载全部队列的软中断待 M1.5 实测。
- 多出来的核若长期空闲,会被并入批处理与冷进程,需防止冷进程扩张挤占 sim。
