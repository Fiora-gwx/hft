# Agent Note: 回收槽原件重送的覆盖边界

Status: implemented

## Problem

默认故障表登记了 LateFillAfterRecycle,实现却没有交付任何回报。只按预定时间延后,无法证明槽已经回收;用新的外来成交套上旧身份,也无法证明原自有订单的墓碑路径。

## Decision

保留实际撮合回报,首份正常交付。只有已提交日志包含这份原件、当前槽不再占用完整旧身份且对应墓碑存在时,才重送同一回报。原撮合费用与拆费后的回报分开保存,晚到副本不再次拆出 FeeOnly。检查器关闭时使用相同观察和调度。

## Alternatives considered

合成零成交撤单回报可以提早回收槽,随后再交付首次成交,但它额外引入了没有撮合来源的终态事实。该行为应另设故障规格,不能混入传输延后并据此宣布新增累计量路径通过。

## Consequences

本项只计真实墓碑重复回报覆盖。新增累计量仍按 [OMS 墓碑契约](../../../../crates/hft-oms/README.md#墓碑与迟到成交c1) 单独验收。完整身份、提交边界、组合传输与恢复见 [TK-166–169](../../../../crates/hft-testkit/TESTS.md#tk-166-回收槽副本保留原件及共同传输扰动),真实文件与 Model 见 [RPL-287](../../../../apps/replayer/TESTS.md#rpl-287-回收槽副本的真实文件与-model-恢复回放)。保留旧参考,依据 CI 逐行迁移当前金样。
