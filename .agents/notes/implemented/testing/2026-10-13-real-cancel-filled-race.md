# Agent Note: 撤单拒绝使用真实撮合事实

Status: implemented

## Problem

默认 CancelRejectFilled 只有计划条目,没有实际交付。撮合器已有终结订单的撤单拒绝,缺少可控的真实撤单与成交交错。直接把成交回报的 kind 改为拒绝,无法证明引擎发过撤单,也容易丢失费用。

## Decision

故障层暂缓原始完整成交,正常交付 Ack。引擎通过已记录的输入发出 Cancel 后,由同一 SimExchange 查实际订单并返回拒绝。只有身份和累计结算均匹配,才在拒绝后交付原件;未触发时有界等待后释放。排队与超时不算竞态成功,不改变撮合量或钱包真值。

## Alternatives considered

仅观察自然撤单拒绝不改变交错,默认种子可能始终绕过目标路径。主动伪造 Cancel 会绕过 OMS 的 PendingCancel 与决策记录,不能验证真实引擎。给交易所临时改价以逼迫挂单成交则引入新的行情语义。本次采用传输延迟,原成交和撤单都由原有入口产生。

## Acceptance criteria

[TK-170–173](../../../../crates/hft-testkit/TESTS.md#tk-170-已成交撤单拒绝来自真实撮合器) 的八行撮合表、五项证据反例和检查器透明性通过。[RPL-288](../../../../apps/replayer/TESTS.md#rpl-288-已成交撤单拒绝的真实文件与-model-回放) 每行真实两次竞态、两次恢复、10000 步,原件费用与现金独立核对。50 行旧金样可重现后才接受有证据的新摘要。

## Risks

查询可能先收敛订单,使后续没有可撤槽;这类样本只记等待或超时。该故障不替代全部撤改竞态规格。默认运行期基础币费用扰动仍分批处理。
