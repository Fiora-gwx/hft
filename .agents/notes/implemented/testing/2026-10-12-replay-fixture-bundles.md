# Agent Note: 整套回放样本固定成员和执行入口

Status: implemented

## Problem

多段回放依赖段之间的 seal 链,Model 窗口验证还需要较早的检查点。分别下载一个文件并核对哈希,不能证明整套输入齐全,也不能约束这份样本实际执行了哪些验证。测试用策略种类又不能进入生产 registry。

## Decision

在现有指针后缀下使用带版本的整套清单,逐文件记录相对位置与运输校验值,同时声明检查矩阵。获取与回放共用解析和校验规则;样本只能选择已知的 registry 或开发测试入口。数据布局与失败行为归 [fixtures](../../../../fixtures/README.md#大文件s3-指针),执行和报告规则归 [xtask](../../../../tools/README.md#cargo-xtask-replay-verify)。

## Alternatives considered

压成一个 tar 对象也能保存目录关系,但引入额外解包工具、归档路径校验和归档内外两套校验语义。逐文件清单可沿用已有的 zstd 与哈希检查,也便于检查每个段与 seal,因此采用它。将测试策略注册进正式二进制会让开发夹具扩展生产种类集合;固定映射到现有 example 则保留测试与生产装配边界。允许清单指定任意命令虽然灵活,却把输入格式变成可执行脚本,不采用。

## Acceptance criteria

[TOOL-198–204](../../../../tools/TESTS.md#tool-198-整套获取与缓存复用) 验证预检、整套发布、复用、反例和检查矩阵;[RPL-281](../../../../apps/replayer/TESTS.md#rpl-281-真实三小时文件经过整套获取与回放入口) 用真实三小时生成文件执行三项回放,坏缓存必须在子进程启动前失败。生成样本不替代固定 T1/T3 或真实 S3/OIDC 证据。

## Risks

解压后的磁盘大小在完成解压后才核对。进程被强杀可能遗留独占锁,清理前须确认没有获取进程。SHA-256 证明缓存与清单相等,不能替代样本来源和负责人评审。并发读取要求样本保持不可变,与正式回放输入契约一致。

## Consequences

固定样本的目录关系、策略入口和检查范围都能在提交中审查,遗漏文件或漏跑重算不再隐藏在手工调用步骤中。生产协议不变,发布固定指针仍须具备专用桶、只读身份和验收证据。
