# Agent Note: 编解码零分配测量限定调用线程

Status: implemented

## Problem

CI 38148402294 的 EVT-196 在未修改编解码代码时记录到 4 次分配。原计数器的开关与累计值是进程全局量,无法区分编解码调用与测试框架其他线程的分配。这种测量不能归因到被测入口。

## Decision

计数器使用常量初始化且无析构器的线程局部量,同时记录分配与释放。先用真实分配验证计数器有效,再让外部线程的分配与测量区间重叠,证明线程边界。编解码入口同步执行,其自身分配仍全部计入。具体用例归 [EVT-196](../../../../crates/hft-event/TESTS.md#evt-196-编解码入口零分配零系统调用)。

## Alternatives considered

- 失败后直接重跑。偶发的全进程分配仍可能污染下一次测量。
- 允许少量分配或只看多次运行的最小值。这样会掩盖真实的编解码分配,破坏零分配契约。
- 引入 hft-testkit 的计数器。它不统计释放,且基础组件的测试不需要为了这个局部计数器增加更高层依赖。

## Consequences

只改变测试测量范围,不改事件代码、格式或资源上限。原有 1,000 次入口调用与 Linux 系统调用检查保留。

## Acceptance criteria

同线程正例为 1/1,外部线程重叠对照为 0/0,热身后的编解码测量为 0/0。完整用例由 GitHub 托管 CI 执行。
