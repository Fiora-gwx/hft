# Agent Note: 未映射回报副本的独立证据

Status: implemented

## Problem

默认旧代数成交经过无 client ID 扰动后,同一笔现货成交先由未匹配副本入账,随后旧代数副本被 OMS 去重。冷账本的 `unmapped_fills` 对两份未映射输入都计数,观察检查却要求每次计数增加都有新的入账注记。CI 258 的五个文件回放样本在副本处失败,其中固定回归种子 0x34b 的原件在 seq 3126 入账,seq 3132 只有零入账告警。原始文件中的资金字段相同。

## Decision

LED-267 在完整事件边界保留已经独立核实入账的原始回报事实。后续副本同时提供相同交易所身份和全部资金字段,以及本事件完整路径身份匹配的零增量注记,才能解释未映射计数。无 client ID 与旧代数副本可以改变客户端槽身份和交付时刻,不能改变成交原件。

入账证据在事件完成后才可供后续事件使用,容量有界且满时失败。恢复重读已提交日志重建证据。新入账仍须同事件一一对应的 OmsForeignFill;已有原件不能解释新增金额,也不能再次要求入账。钱包逐单位一致的契约保留。

## Alternatives considered

**继续把每次未映射计数都当作新入账。** 冷消费者对现货重复输入仍增加计数,但引擎正确去重后没有第二次入账注记。将告警当成漏记账会拒绝正确行为。

**看到零入账注记就放行。** 注记本身不能证明原件已入账,也不能排除同订单的新数量或错误费用。必须由先前完整事件的原始事实共同证明,缺失任一证据都失败。

## Consequences

该变更只影响 DST 冷观察检查,没有改变生产记账、事件 schema 或快照。字段破坏、缺原件、错注记、重复入账及容量边界归 [LED-267](../../../../crates/hft-ledger/TESTS.md#led-267-dst-中每个快照点-journalledger-等于引擎-ledger)。默认组合扰动继续进入 [RPL-012](../../../../apps/replayer/TESTS.md#rpl-012-dst-生成的种子-journal-全部回放一致),定向文件恢复归 RPL-286。
