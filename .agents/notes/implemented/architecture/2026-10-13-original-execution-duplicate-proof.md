# Agent Note: 按原始单笔成交证明跨来源重复

Status: implemented

## Problem

用户要求保留引擎钱包与交易所钱包逐单位一致。LED-080 的外来成交可能先以 Unknown 原件入账,再收到同订单累计回报。仅凭数量相等或 ext_held 不能证明现金和费用重叠,放行会掩盖重复扣款,按两种顺序各算一个参考钱包也不满足该要求。

## Decision

先支持能由完整原始事实证明的单笔前缀重复。仅在原件实际完整入账后保留有界证据,冷热消费者各自核对累计身份、数量和金融字段。证明随 OMS 快照恢复,普通去重环淘汰不能让它失效;不同成交键使单笔条件永久失效。具体支持范围、字段和容量归 [OMS](../../../../crates/hft-oms/README.md#回报匹配与成交增量),独立核验归 [ledger](../../../../crates/hft-ledger/README.md#冷消费者journalledger)。

## Alternatives considered

用实际钱包差额反推期望值会让同一错误进入两侧。按累计量比例拆分现金不能还原跨价格与跨方向成交的实际结算。把外来来源无条件改为累计水位会误认跨多笔前缀。对无证据的方向继续明确失败,不借这次有限支持声称一般跨来源问题已解决。

## Acceptance criteria

OMS-477–479 检查原件、反例和旧格式;LED-296/297 独立核对并覆盖去重淘汰;SEQ-419/420 核对钱包、无重复对冲及完整/窗口回放;RPL-282 使用实际写入器文件和 replayer CLI。LED-080 仍需真实撮合场景及标准和日期种子验收,本前置不能代替它。所有构建和执行在托管 CI 完成。

## Risks

证明增加持久状态,旧格式恢复不能补造。先累计后原件、多笔累计重叠、普通槽重新认领仍不支持。PR 保持草稿,资金和恢复变更待负责人评审后合并。
