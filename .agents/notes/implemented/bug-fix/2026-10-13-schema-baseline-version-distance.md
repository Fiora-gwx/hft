# Agent Note: 只追加核对允许跨过多次版本追加

Status: implemented

## Problem

PR 的 schema 基线取合并基点。一个长分支中先追加现金字段,再追加成交 ID,当前版本与合并基点相差两次。强制只差一个版本会拒绝合法前缀扩展,CI 225 因此未生成 OrderEvent 的 schema。生成物检查仍应比较完整分支的所有改动。

## Decision

布局变化要求版本严格高于比较基线,任何版本回退都失败。每次追加仍按事件演进规则加一,端点比较允许经历多次追加。字段名、类型、偏移、前缀和编号的保护全部保留,具体契约归 [hft-event](../../../../crates/hft-event/README.md#实现说明)。

## Alternatives considered

只与 HEAD 的 lock 比较会让已提交的删除或编号复用避开 PR 基线保护。把当前事件版本降回已使用的版本会抹掉中间布局演进。两种做法均不采用。

## Acceptance criteria

[TOOL-061](../../../../tools/TESTS.md#tool-061-gen-schema---check-拒绝违反只追加核对的改动) 覆盖跨两次合法追加、不升版本、版本回退和升版本时改名旧字段。现有 EVT-175/182 的字段保护与 PR 合并基点用例保持通过。

## Risks

端点检查不证明分支中每个中间提交均可发布;发布仍依赖该 SHA 的完整质量门和生成物一致性。CI 生成的二进制金样须核对字节差异后提交,不能仅因生成器运行成功就视为验收通过。
