# Agent Note: 实际连接身份与启动余额基线

Status: implemented

## Problem

双 venue demo 的严格预检后，Shadow 收到了 Order Up 的 ConnId 112 以上，但启动闸门始终不放行。另一个独立故障发生在 seq 22：引导快照已有余额，首次实时余额输入仍发出建基线遗留的 BalanceInit，冷账本拒绝并造成逐字节回放分歧。

## Decision

每配置账户/venue 预分配两组定长连接位图，按真实 ConnId 幂等更新。可用订单连接数决定主路与热备健康；用户流轮换按存活集合聚合。快照节 30 保存这些决策状态，真实恢复结束清空旧进程连接。旧快照缺节时保留旧解释供历史日志回放。

账户 bootstrap 的余额属于初始快照。其临时 notes 在写引导块之前清空；后续 BalanceReport 只能产生与该实时输入对应的余额校验。

## Alternatives considered

**修改闸门或伪造 0/1 连接号**：会掩盖真实状态，破坏轮换与延迟关联，未采用。连接号仍由网关分配并原样记录。

**从风险闸门反推连接集合**：两个布尔值不能恢复真实成员身份，后续旧连接 Down 可错误覆盖新连接，故使用追加快照节。

## Consequences

启动期按已配置账户数分配，运行期不扩容。快照多存实际连接集合并纳入状态哈希；冷启动重新取得健康证据。SEQ-160 覆盖轮换、重复消息及关键帧回放，SEQ-414 覆盖双 venue 启动基线的冷热账本与回放。资金/恢复修复记录在 docs/changes.md 待评审；测试网任务负责人已授权通过全部 CI 后自行合并更安全的 bug fix。
