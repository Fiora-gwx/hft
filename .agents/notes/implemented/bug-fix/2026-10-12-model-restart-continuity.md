# Agent Note: Model 来源跨重启连续性

Status: implemented

## Problem

检查点可以早于一次或多次进程重启。引擎状态必须从每次启动的快照恢复,但 Model 的原始样本来自检查点与其后完整输入。每遇重启就丢弃已重算的 Model 会把有来源的实例误报为 model_no_start。在线 advisor 若沿用旧引擎镜像,又会在旧 Drain 停住或向 Model 提供旧状态。路径重置注记的原因码若按实例编号校验,实例 1 会掩盖错误。

## Decision

advisor 追赶在进程边界切换到记录的引导快照和配置,身份匹配的 Model 随输入续算。恢复失败显式保存在 failure。冷重算只延续具有合法起点、连续前缀及相同实例身份和参数引用的状态;来源不明的仍逐名报告。比较窗口前的重置注记参与重建边界计算,原因码遵循事件格式,时间使用 engine_ns。advisor 的追赶会重发旧 basis;因此原始产出字节按既有容量限制保留,只在进入新运行时重新允许一次匹配。同一运行重复与跨运行篡改都不能通过。

这收窄 [离线起点决定](../architecture/2026-10-12-offline-model-origin.md) 的逐运行对象隔离要求。引擎运行仍完全隔离,Model 来源则依照检查点和 journal 判断。

## Alternatives considered

**每个运行空起步。** 无法恢复检查点内的累计样本,违背跨重启续算契约。

**沿用整个旧镜像。** 不能应用恢复时的引擎状态变换,也不能处理 Drain 后的新运行。

**按 UTC 等待路径收敛。** 会把停机时间算进重建期,过早比较近似状态的 Advice。

## Consequences

RPL-058–060 使用真实 Drain、10 分钟停机、TSC 重置和倍频恢复,独立进程检查输出、模型与原始样本累计。RPL-272 覆盖原因、保留位、缺重置与缺来源反例;RPL-273 覆盖路径保留的两次恢复、真实追赶重发及其字节篡改。journal schema 和快照布局不变。镜像重建属于 advisor 的冷恢复工作,单次重建成本仍需参考机测量;本批不声称满足运行时间片预算。资金和恢复改动保持负责人评审。
