# Agent Note: 恢复缺口的验证范围与 Model 来源

Status: implemented

## Problem

冷恢复可能丢失 RAM 中尚未持久化的尾部,随后从磁盘末尾继续分配相邻 seq。只看序号跳跃会漏掉这种缺口。直接拒绝整组文件又无法检查恢复后的实际输出。Model 的样本和旧 Advice 不能从缺口前证明缺口后的连续性。

## Decision

不可变文件读者提供显式恢复入口,仍预检每个文件、段链哈希和完整事件,只允许段头声明的恢复缺口。默认严格入口不变。逻辑日志保留全部标记,冷回放要求它们落在恢复引导块,引擎逐运行从快照恢复。报告同时公开数值缺口与未知尾部,通过结果只覆盖所给记录。

冷 Model 重算在标记处清除已续算样本和历史配对。缺口后的检查点、创建或丢弃注记可以建立新来源;前段 End 上的检查点仍位于缺口前。这具体化 [跨重启连续性决定](2026-10-12-model-restart-continuity.md) 的完整前缀前提,不改变在线 advisor 的恢复策略。

## Alternatives considered

**所有缺口都拒绝。** 原严格文件入口采用此办法,保留它供需要连续输入的调用方使用,但它无法给出恢复后输出的验证结果。

**跳过缺口后继续旧状态。** 日志不能提供丢失输入,引擎必须重新恢复快照,Model 也不能借用旧配对记录制造通过。

**只检测不连续 seq。** [JNL-065](../../../../crates/hft-journal/TESTS.md#jnl-065-热目录为空且冷副本末段未封存截断并置-recovery_gap) 的掉电恢复并不保证留下数值空洞。

## Consequences

JNL-131 与 RPL-275–278 覆盖连续标记、跳号、后缀、重复恢复、检查点两侧、错误边界和恢复后的输出/Advice 反例。诊断数量随既有记录数上界受限,文件、journal schema、快照及热路径不变。报告不能证明未知尾部或替代完整上线验收;相关恢复改动仍交负责人评审。
