# Agent Note: 策略定时器的身份历史随快照恢复

Status: implemented

## Problem

SDK 允许策略持有 TimerId 并在重启后继续取消。定时器堆只保存截止、tag 和 group,恢复时按遍历顺序重新编号。取消或到期留下编号空洞,截止顺序也不等于分配顺序;即使堆为空,仍可能已消耗许多 ID。[配额与取消修复](2026-10-12-strategy-timer-admission.md) 只补齐运行期身份,不能保证这项持久化契约。

## Decision

用独立快照节保存每个绑定实例的计数器和存活登记,登记按 ID 排序。恢复同时核对实例集合、ID 约束与堆的完整多重集合,保留相同物理键的登记条数。截止是已有堆时间的副本,加入相同的 D6 登记,两处在恢复结束时一起平移。行布局与失败规则归 [sequencer 快照](../../../../crates/hft-sequencer/README.md#快照)。

缺少身份历史的旧开发快照不能靠空堆推断计数器,有绑定实例时明确拒绝。上一版本虽然能跳过未知节,却没有稳定 ID 的行为保证,不能将它列为使用该能力的已验证回滚版本。该兼容边界要在合并评审中明示。

## Alternatives considered

**按堆顺序补号**不能保留空洞与已消耗计数。**把元数据塞进策略状态**侵犯策略自己的序列化边界。**改变节 5 行头或节 8 固定行宽**会触及旧读者的固定布局解析。**按节 8 的排序下标保存映射**少存一份截止,但需要写出时额外排序配对,且相同物理键必须另定绑定规则。直接保存登记表不改变运行路径或堆格式,恢复侧做有界集合核验即可;代价是每条登记多一份截止,后续快照内存与延迟验收须计入。

## Consequences

[SEQ-408–410](../../../../crates/hft-sequencer/TESTS.md#seq-408-策略持有的-timerid-经崩溃drain-与连续重启保持有效) 使用策略自己的状态保存 ID,覆盖跨频率的崩溃、Drain、连续重启、同键登记、空堆续号和损坏拒绝;完整与窗口回放都核对输出和恢复状态。节内容参与现有 state_hash,不增加哈希豁免。该改动不宣称解决快照整体的分配或参考主机延迟门槛。
