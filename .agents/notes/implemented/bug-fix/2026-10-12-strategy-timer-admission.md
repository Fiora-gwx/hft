# Agent Note: 策略定时器在调用时预留共享配额

Status: implemented

## Problem

[SEQ-350](../../../../crates/hft-sequencer/TESTS.md#seq-350-策略定时器超出共享配额时-timer_at-返回-ctxfull不进堆) 要求超额的 timer_at 当场返回 CtxFull。SDK 只检查事件数组,sequencer 等全部回调结束才拒绝超额请求,调用者已经保存了一个未登记的 ID。多个实例与同一实例的多次回调还会竞争同一配额。取消只记录 ID,但应用时按 tag/group 删除全部堆条目,可能删掉另一份独立登记,并使登记表与堆的数量不一致。

## Decision

每轮保留一份共享余额,依照现有实例和回调顺序借给 SDK。timer_at 在成功返回前预留;取消从只读登记表与本轮请求中核对 ID,只有当时确实存在且尚未释放的登记返还一格。未知取消不预订未来行为,被取消缓冲丢弃的请求不返还容量。全部 Ctx 仍在原来的时点按原顺序应用。应用时违背已承诺配额属于 TimerOverflow,不能把成功变为静默丢弃。

登记表保留 TimerId、tag、group 和本运行的截止,按 ID 升序。取消和到期只删去对应截止的一条;跨重启的截止使用与堆一致的平移。表在实例构造时按配置上界预分配,SDK 不分配内存。取消对已登记 ID 作二分查找,并扫描至多八项的本轮缓冲。

## Alternatives considered

**只在 apply_ctx 拒绝**不能满足调用时的返回值契约。**为每个实例分别提供完整余额**会重复承诺同一格。**每次回调后立即应用 Ctx**改变后续实例看见的视图和原有意图顺序。**取消按 tag 批量删除**会把另一份 TimerId 的登记一起删掉,也无法按一次有效取消返还一格。

## Consequences

事件数组上限与共享配额分别检查,满计数每实例每轮汇总一次。SEQ-350 覆盖五种实际投递路径,SEQ-407 覆盖同 tag、重复/未知取消与重新登记,两者含完整与快照窗口回放。SDK-212 检查跨回调余额、取消顺序、数组上限与 ID 耗尽。SEQ-236 至少运行 1000 个属性样本,环境配置可提高数量。

本改动不改变 journal 与快照布局。SDK 要求的 TimerId 跨重启稳定尚有独立缺口,当前恢复会按堆顺序重新编号;需要保存计数器和身份映射,并以包含 ID 空洞与截止重排的真实重启验证后再计完成。该缺口归属 [sequencer 限制](../../../../crates/hft-sequencer/README.md#已知限制与后续工作)。
