# Agent Note: 外来累计结算的来源与水位

Status: implemented — PR #2 内待 CI 与资金、恢复评审

## Problem

严格钱包契约要求记入实际永续结算。普通订单已有完整身份水位,未知槽的完整累计回报仍被一律拒绝。直接把累计现金当本笔金额会重复入账,只在内存保存水位又会在重启后重复。

## Decision

不重叠外来订单按 venue、账户、品种、交易所订单号保存已接受的累计毛量和实际现金。原始 ExternalFill 的非零订单号保留另一种来源,禁止在原始逐笔与外来累计两条路径间重新入账。来源表与累计水位共用预分配容量,满时失败,不使用 FIFO 淘汰。字段与错误契约归 [OMS](../../../../crates/hft-oms/README.md#回报匹配与成交增量)。

快照节 12 追加 ForeignCash 行。有该行时写 v3,没有时保持可由 v2 表达的既有编码。冷读者恢复该行,从原始 OrderEvent 和自身水位独立计算增量,同事件的 OmsForeignFill 只证明路由及原始入账字段。没有该证据或内容冲突均失败,不从热账本钱包或注记反推现金。

## Alternatives considered

按数量比例扣除已有外来现金不能证明成交区间及逐笔价格。当前输入也不能恢复所有交叉区间,因此跨来源重叠和 AUTO_EXTERNAL 不纳入本批支持范围,继续明确失败。

把现金增量另写一个注记会把热端计算结果交给冷端作为答案。复用原始累计输入与持久水位可让两边独立计算,无须增加 journal 事件字段。

## Consequences

这批覆盖不等于 LED-080/081 完成。过保留期的系统订单重新归属、交叉区间和对账补量还需原始结算事实及独立 DST 验证。M2 不标完成,PR 保持草稿。新增快照行、现金入口和恢复路径须经负责人评审后才能合并。

## Validation

OMS-471–474 检查乱序、恢复、重复、坏事实、容量与来源查询预算;LED-290 独立计算并拒绝错误或缺失同事件证据;SEQ-415 验证真实引擎的完整与窗口回放。既有 DST 种子、步数、固定 HashTrail 和基准冒烟强度保持不变。构建和测试仅在 GitHub 托管 CI 执行。
