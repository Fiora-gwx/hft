## 结论

**选定 apne1-az4**(本账号中的可用区名 `ap-northeast-1a`;以 AZ ID 为准,名字在不同账号中映射不同)。

| 交易所 | apne1-az4 | apne1-az1 | apne1-az2 |
|---|---|---|---|
| Binance(fstream/ws-fapi/fapi/api1–4,全部 IP 的最小 TCP 握手) | **0.17–0.19 ms** | 1.67–1.73 ms | 1.61–1.67 ms |
| Bitget WS | **0.21 ms** | 0.26–0.31 ms | 0.89–0.92 ms |
| Bitget REST | 1.40–1.48 ms | 1.45–1.54 ms | 1.65–1.70 ms |
| OKX WS / REST | 1.23–1.41 ms | 1.24–1.43 ms | 1.21–1.34 ms |

- Binance 的全部交易与行情端点都在 az4:在 az4 内约 0.18 ms,跨 AZ 约 1.65 ms(与 2026-10-01 从 dev2(az2)测得的 ~1.35 ms 量级一致)。`api.binance.com` 在 az1/az2 的低值是边缘节点,不代表交易端点。
- Bitget WS 在 az4 最近,az1 次之;OKX 在三个 AZ 都约 1.2–1.4 ms(不在这三个 AZ 内,选 AZ 对它无影响)。
- 同一 AZ 内三台实例的差异 < 0.03 ms(同一 CPG),CPG 之间的差异本次未测(每 AZ 只一个 CPG),M1.5 主探针的 CPG 内再看。
- TLS 握手中位数:Binance 在 az4 2.1 ms、其余 AZ 约 3.8 ms;OKX 约 4.4 ms;Bitget 约 3.6–4.0 ms。
- 首帧单向延迟这次没有校准时钟(实例未配 PHC/chrony 同步,`clock = unsynced`),只能看相对值:Binance fstream 首帧最小值 az4 0.77–0.94 ms,az1/az2 1.27–1.84 ms。
