# M0-c 后独立评审 V1:交易路径的资金与状态正确性(2026-10-03)

> 无上下文子代理只读评审原文(主控已抽查 P0-1、P1-1 出处属实)。路径相对 `E:\trading\hft\`。

## §1 结论

- 主干设计很严,可以进入实现:Unknown 纪律、第二腿不超过裸量、对冲量上限、32 位 KillWord、模式与 cap 分离、引擎时间都已到位。
- 但引擎自己的减仓/平仓路径,以及 Broken 与恢复之间的交互,在真实故障组合下仍会留下裸腿或卡住强平保护。
- 两个 P0 都在 hft-exec 的引擎单路径上:一是 L3/flatten 依赖另一所的报价,二是引擎单的限价和名义没有与风控 #5/#6 对齐。
- 9 个 P1;P2 多是同一事实在多处说法不一致;待核实标注总体合格,漏标见 P1-8 与 P2-13。

## §2 发现

### P0

**P0-1 L3 与 Kill{flatten} 对非 Broken cell 走 PairOnFill,必须两腿报价都健康;另一所行情断开时永续减仓完全停摆**
- 场景:Binance 永续空、OKX 现货多,急涨,Binance `liq_dist ≤ 0.10` 进 L3,每 5 s 一次 ForceDeleverage;OKX 公共 WS 断线或重同步,现货腿 `quote_ok = false` → PairOnFill 预检不过,第一腿(永续 reduce-only 买回)不发,cell 卡 `Stuck{StaleQuote}`;不是 Broken 所以不走"永续先"串行路径;`Kill{Account, flatten}` 同理。
- 引用:`crates/hft-exec/README.md:489`「非 Broken 的 cell:`PairOnFill{first_leg: PerpFirst, …}`」;`:364`「两腿都须 `quote_ok`」;`:307`;`:495`。
- 修复(hft-exec):`reason ∈ {MarginStress, Hard}` 时只要求永续腿可用;第二腿不可用时退回 Broken 的串行路径(永续 reduce-only 先减),接受短时现货裸多并报 P0;DST"L3 + 另一所 BBO 断 30 s → 永续仍按步减"。

**P0-2 引擎减仓/补腿单的限价与单笔名义没有钳到风控 #5/#6 的口径**
- 场景 a(价格带):执行层限价 = 对手价 × (1 + `force_slice.max_cross` 0.5%),风控只放行 ≤ mid × (1 + `rr_max_cross`);价差扩大时永续买回单每次被 PX_BAND 拒,当门控退避后同口径重算,永远发不出去;OMS `price_hedge` 会夹到 cap,执行层没有;`RiskStateView` 无 `rr_max_cross`。
- 场景 b(名义):Flatten 切片量 = `max_reduce_notional / 对手价`,限价却是对手价 × 1.005;`IntentView.notional` 口径未定义,按限价计则超上限被 #6 拒;Open 切片也没按 `max_order_notional` 截量。
- 引用:`crates/hft-exec/README.md:417`、`:453`、`:349`、`:188`、`:506`;`crates/hft-risk/README.md:262`、`:263`、`:95`;对照 `crates/hft-oms/README.md:489`。
- 修复:hft-risk 在 `RiskStateView` 暴露 `rr_max_cross`,定义 `notional = qty × 限价`;hft-exec 引擎/对冲单限价 = min(对手价 × (1 + max_cross), cap),与 `price_hedge` 共用同一函数,数量按限价折算;参数校验 `force_slice.max_cross ≤ rr_max_cross`、`max_chunk ≤ max_order_notional`;Flatten/ForceStep 被 #5/#6 拒按执行失败处理并报 P0。

### P1

1. **Broken 按"含在途"裸量自动解除**(`hft-risk:49`、`:571`;`hft-exec:299/433/464`;`hft-oms:531`;`hft-sequencer:284`):自动平仓 IOC 发出即 |1.0−1.0| = 0 → AutoClear;IOC 零成交则裸露恢复但非 Broken,"至多一次"失效;对冲腿 Unknown 时也会立刻解除。修:解除 = 已成交裸量 × mark ≤ dust 且无 Pending*/Unknown/在途;自动平仓成功判定同口径、每片终态后判断。
2. **外来成交在 flatten/L3 期间暂停并清除引擎目标**(`hft-exec:479/481/497/525/299`):ADL 后 `on_external` 暂停 5 s,截止清掉引擎的 0 目标,flatten_lock 仍在。修:只暂停 `origin = Strategy` 的目标;Engine 来源、`force_active`、`flatten_lock` 账户不暂停不清除;Broken cell 保持 Broken。
3. **BboView 只按最近一条 Bbo 所在连接投影健康**(`hft-sequencer:275/268`;对照 `hft-venue:249`、`:250`;SDK:399):赛马胜出连接退役后,安静 inst 被判报价不可用;Binance 每 24 h 强断即触发。修:按 (inst, conn) 维护成员位图,`conn_up` = 任一成员 Up,`conn_live_tsc` = Up 成员最大值;节 10/26 扩展。
4. **recovery_end 的 `now` 来自 RecoverDriver::stamp()(日志值)**(`hft-sequencer:468`、`:57`;`hft-oms:116-117`):整机重启后定时器落到极远将来,Broken 自动平仓、外来成交截止、Unknown 超时永不触发。修:`now` 取本次运行 TscClock,写入 Recovery 快照头。
5. **RESUME_HOLD 续接对冲绑定整个启动闸门,无上限、无 P0**(`hft-oms:564/543`;`hft-risk:336/343`;`hft-core:418`)。修:只等对冲腿 venue 的 IDENTITY + ACCOUNT_CFG + ORDER_CONNS 且该链接无 Unknown;`resume_hold_max_ms` 超时 → Broken + P0。
6. **resolve_broken 没有尘埃阈值**(`hft-oms:59`;`hft-risk:287/317/332`;`hft-sequencer:384`;`hft-exec:445`):亚尘埃残余在闸门放行时被设 Broken + HedgeFailure,全账户禁开。修:`naked_groups` 按 `dust_notional` 过滤;设 Broken 后同一 Input 内调一次 `on_legs`。
7. **BalanceOnlyPush 钱包入账不按笔追踪**(`hft-ledger:252/257/281`;`reconciler:84`;`hft-venue-proto:339`;`hft-venue:336`):推送丢失 → 钱包从未变化但 Funding 条目差额 ≈ 0 不校正 → USDT 余额差 → Recon;推送重复 → 重复入账。修:按 (account, venue, settle_ts) 记已入钱包额;reconciler 对这类 venue 的 `engine_amount` 取已入钱包额,差额用 `AdjustDelta::Funding` 动钱包;FundingSettle 推送纳入去重。
8. **Binance 成交历史不带 client id,`history_checked = 1` 判据未定义**(`reconciler:130/266`;`venue-binance:141`;`hft-oms:403`):-1007 未 Ack 的对冲腿可能被判 NotFound → SecondRetry → 迟到成交双重对冲。修:窗口内存在不属于已知槽/外来单的 orderId 成交 → `history_checked = 0` + P0;Binance grace 后按 client id 复查两次仍 -2013 且无未归属成交才给 1;写入 README。
9. **挂着的 GTC/PostOnly 计入 in_flight,被当作对冲覆盖**(`hft-oms:531/542/465/543`):永续腿挂卖 1.0 GTC,现货买 1.0 成交后 naked_dir = 0,第二腿为 0,补腿被抑制,现货裸多无界。修:in_flight 拆成"IOC/FOK/Pending*/Unknown"与"resting",naked 与补腿抑制只用前者;或风控禁止在带 LegLink 的腿上挂 resting 单。
