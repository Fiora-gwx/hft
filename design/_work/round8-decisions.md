## R8-1 范围:新框架首要服务 CEX-CEX

- 新框架主要运行 CEX-CEX(ccex)策略。cdex 继续在旧框架运行,迁移不急,不在本轮 core。
- 链上全部转 `optional`:`apps/chain-core`、`hft-chain-evm`、`hft-ext-proto`、`contracts/`(SwapGuard)、`hft-amm`、`chain-grpc-relay`、`hft-chain-solana`、策略 D/E。外部 venue 协议在架构上保留(接口与事件编号段不删),以便日后接入。
- ccex 策略族:**组合携带**(永续空 × 现货多,资金费 + 基差;以老板的 portfolio-arb 为雏形)是第一个实现的策略;腿模型通用,使"跨所永续 × 永续资金费差""同所现货 × 永续"只需新策略 + 配置即可接入;跨所价差吃单(原 A)、挂单 + 吃单对冲(原 B)预留。方向只做"空永续、多现货",反向(需现货借币)不做。
- 交易所不固定(Binance、Gate、Bitget 等均可能)。**策略代码中不出现交易所名字**;交易所差异(手续费扣币种、reduceOnly 是否支持、最小名义、资金费推送方式、持仓模式、限速)由 venue 适配层与 refdata 的能力表表达。首批实现哪两三家,在 venue 接入开始前确定。
- portfolio-arb 是策略雏形,不修、不迁移、不作为验收对照基准;其已知缺陷(见评审 §6)不得照搬。

## R8-2 目标顺序:延迟优先,其次正确性与可扩展

- 总目标保持 **p50/p99 延迟优先**,其次正确性、可扩展。微秒级机制(忙等绑核、RAM journal + persist、帧模板、热备连接、conn-builder、BBO 独立连接等)保留为 core 设计。
- 开发与测试暂在**本地 + 现有服务器(dev2 主机类)**进行;dev2 只做功能与正确性验证、不做延迟验收。"大体没问题后统一升级"到 c8(或更高)主机类,延迟验收在升级后进行。
- 现有服务器同时跑 cdex 正式账户:新框架在其上运行时必须受资源上限约束(见修改方案 §M0 的 dev2 护栏),不得影响 cdex。

## R8-3 策略与工程解耦(硬要求)

1. **策略包**:每个策略一个独立 crate(`strategies/<name>`),只依赖稳定的策略 SDK crate(及可选的通用构件库);静态编译进同一二进制,改策略代码需重新发布,参数热更新。新增或修改策略**不得修改任何引擎 crate**(sequencer、OMS、risk、ledger、journal、venue、event、refdata、ctl);装配处(app)只增加一行注册。
2. **策略包 = 快速部分 + 慢速部分 + 参数 schema**:快速部分在 sequencer 里处理事件;慢速部分(打分、分配、分位、资金费统计等)属于同一策略包,在 advisor 线程运行,输出以通用、不透明载荷的 Advice 进入 journal;不再要求在公共事件 crate 登记 AdviceKind。Python 只做研究与分钟级以上的选币/名单。
3. **输出两层**:策略可输出目标仓位(引擎执行层负责切片、双腿协调、对冲、补腿),也可直接输出订单意图。执行算法(吃单切片、两腿 OnFill、目标跟踪、先挂单后对冲〔预留〕)是可复用的工程模块,策略选用。
4. **风控边界**:引擎负责全账户硬限额、kill、保证金率、裸腿、限速、对账、交易所能力约束;策略负责自己的进出场与止损。现有规格中写进引擎的策略规则(资金公式 `wallet × leverage × deployable`、cdex 补腿 5% 阈值、cdex 残余清理规则等)移到策略参数或策略代码。
5. **参数 schema 驱动**:每个策略自带参数 schema(字段、单位、范围、默认值、说明);配置工具、控制协议、ops_bot 按 schema 通用处理,新增策略不改它们的代码。
6. 解耦由机检保证:依赖方向检查(引擎 crate 不依赖任何策略 crate;策略 crate 只依赖 SDK 与通用构件)、doc-check(引擎 README 不出现策略族名)。

## R8-4 账户与资金

- 一个交易所(子)账户只给一个策略实例使用;C(ccex)与 D(cdex)分开。
- 跨所资金:只告警 + 给划转建议,不自动划转、交易 key 不带提现权限;保证金危急时由引擎按分档规则自动降级与减仓。treasury(监控 + 建议)转 core。
- ccex 策略用新开的子账户直接上线,不涉及接管旧仓位;迁移手册与"现货腿采纳入账"降为 optional(cdex 迁移时再做)。

## R8-5 不做回测系统,做模拟系统

- 不建历史回测系统用于评估策略(用户判断回测一定不准):`hft-sim` 的 hftbacktest 假设回放、`replayer` 的假设模式与参数扫描、research 的回测流程不进 core。
- 建**模拟系统**:实时行情 + 模拟撮合 + 模拟账户,策略代码与实盘完全相同,用于观察策略表现并改进。形态为一等公民的**模拟账户**(账户类型 `Sim`):策略在模拟账户上以正常模式运行,订单不发往交易所而进入进程内模拟网关,回报经同一回报环进入并记入 journal(回放仍确定)。可同时开多个模拟账户跑不同参数。
- 确定性回放(`replayer verify`)保留,用于正确性与排障,不用于评估策略收益。
- 小额实盘开始后,同参数的模拟账户与实盘并行,用实盘结果校准模拟(滑点、成交率、延迟)。
