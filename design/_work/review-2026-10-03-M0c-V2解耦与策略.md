# M0-c 后独立评审 V2:策略/引擎解耦与 portfolio-carry(2026-10-03)

> 无上下文子代理只读评审原文。路径相对 `E:\trading\hft\`(pc = `strategies/portfolio-carry/README.md`)。

## §1 结论

1. 解耦骨架成立:依赖方向清楚、registry 一行注册、schema 与描述符驱动工具、Advice 与预热载荷不透明、人工命令走通用 `StrategyCmd`;纯靠 SDK 能写出"跨所永续×永续"和"跨所吃单"。
2. 但"新增策略不改引擎、app、框架"现在做不到:hft-core 的 advisor 内存与容量表按首个策略定、SDK 无 Model 内存声明;treasury 只算永续空头上涨方向;SDK 缺能力(看不到杠杆、拿不到行情接收时间、不能订阅不在 group 里的行情)。
3. portfolio-carry 无 P0,有 9 个 P1。
4. 确定性规则本身正确,问题在检查点语义与验证链。

## §2 发现

### P1

**P1-1 新增策略仍要改 app 配置;SDK 无 Model 内存声明;改参数可致 OOM**:`pct_window_ms` 30 d + 5 s 采样 → 每 group 约 4.1 MB,64 group ≈ 265 MB 超 dev2 sim advisor 256 MiB;检查点 u16 约 133 MB 超 `model_snapshot_max` 64 MiB;再把 `pct_sample_ms` 调到 1 s → 1.3 GB 超 hft-core `MemoryMax`,OOM;pipeline 的 SetParams 中性不需确认;cdex 每 group 约 2.1 MiB(hft-strat-lib:406)。依据:hft-core:291、:292、:308、:694;SDK:78–86、111–125;R8-3(1);cookbook:56;testing:296。修:SDK `Model::mem_bytes(p, groups)` 与 `snapshot_bytes`;ctl-gateway 在 validate 时查 advisor 预算;hft-core 按各策略声明求和;portfolio-carry `check()` 给 `pct_*` 内存与快照上界;门槛 ⑧ 的测试策略带 > 1 MiB/group 的 Model。

**P1-2 负资金费平仓门只修了一半**:VIP0 taker(永续 5–6 bp、现货 10 bp)下 `cost = 2×(5+10) + 半价差 ≈ 31 bp`;倍数条件 `gain×2 < 31` 且 `gain < 31` 时拒,|T| < 15.5 bp/日的负资金费 group 一律不平。依据:pc:208、:211、:543–544;`cost` 的「2 ×(…)// 开 + 平两腿」把沉没的开仓费算进退出成本;`gain_daily + one_shot` 量纲混用(:604 批评过雏形同问题);:195–196 退出分位与资金费正负无关。修:平仓方向成本只算平仓两腿 taker + 半价差(换仓时再加目标币开仓成本);倍数条件只用于开仓或改同量纲;测试用 refdata 真实费率;补一条默认生效的负资金费退出规则(参考 `neg_streak`)。

**P1-3 `Exec{Stuck}` 处理不区分目标原因,会清掉 exit、Hard、MarginStress 目标**:pc:249「含其他风控位 → clear_target…;SliceFails → clear_target」不分 reason;:215 阶段 Exit 等 Done;:244 只有 `force_exit` 参数路径会重设 0/0;外来成交后的 Hard 目标被清,执行层也不触发默认处理(exec:480 把 clear_target 当已处理)。修:只对 `reason = Rebalance` clear;Exit/Hard/MarginStress 保留,`fail_cooldown_ms` 后重发并写 P1 Note;`Exit{Cmd}` 保存命令字段以便重发。

**P1-4 LotMismatch 时"Exit/Hard/MarginStress 照常"不成立**:两腿 lot 互不整除(0.003 与 0.002)、价涨后 lcm 名义 > `slice_max_chunk` 500 → 所有 PairOnFill 目标被拒,只剩引擎 L3/flatten。依据:pc:253、:166、:172–175;exec:380 无按原因豁免;exec:377 又说切片取一个 pair_lot 不卡住;SetParams 用 `force_slice.max_chunk`(1 000,exec:379)与 set_target 阈值不同。修:exec:380 对减仓/Exit/Hard/MarginStress 不做 LotMismatch 拒绝;或风险/退出目标用 max(slice_max_chunk, pair_lot 名义);两处阈值统一。

**P1-5 改结构性 Model 参数时检查点被错解释或统计反复被清**:A:`pct_bin` 1 bp → 0.5 bp 后重启,u16 箱号按新配置解释,`open_th`/`close_th` 全错;B:实现者在 on_params 无条件 new,pipeline 每 30 min 改 `liq_score` 就清 168 h 统计。依据:SDK:174;hft-strat-lib:359(snapshot 不存 PctConfig);pc:497、:348–352;SDK:119。修:strat-lib 快照写入 PctConfig,变化时 rebin 或按 group 重置并写 Note;SDK 规定 `Model::on_params` 区分结构参数;pc 列出结构参数与规则;pipeline 在结构参数变化时触发预热。

**P1-6 检查点金样规则让每次改策略逻辑都丢 168 h 统计**:SDK:179「字节变化而 LAYOUT_VERSION 未变 → CI 失败」;pc:497 检查点含派生状态;与 R8-8、07:46 冲突。修:金样比对改比布局描述(节标签、元素类型、长度);检查点只持久原始样本(两侧环、资金费环、`kline_until_ns`),派生状态恢复后重算。

**P1-7 GroupId 可能被复用到另一个币**:移除 X、新增 Y,框架按"最小空闲 id"给 Y → 快速部分、Model、路上的 Advice 都按 id 对齐到 Y,Y 用 X 的阈值立即开仓。依据:hft-types:148(无"不复用");pipeline:57;SDK:105/:119;hft-sequencer:335。修:GroupId 单调分配永不复用;SDK 要求 on_params 比对 GroupSpec (asset, legs) 指纹,不一致就重置;sequencer 丢弃指纹变化前产生的 Advice。

**P1-8 每日 `--advice recompute` 没有 Model 起点状态,门槛 ⑦ 永远过不了**:testing:255、:295;replayer:34 verify 无 `--model-checkpoint`(只有 sim 有,:36/:66);hft-core:302 检查点只保留两代。修:journal-archiver 每天日界附近归档一份检查点;`replayer verify` 加 `--model-checkpoint`;testing ⑦ 写明 recompute 起点规则。

**P1-9 `perp_margin_frac` 与杠杆的耦合论证错误,真正的安全阀没有机检**:开仓按 avail_margin 增量判断(pc:81),反复开仓收敛到 N ≈ L·M,与 `perp_margin_frac` 无关;决定安全的是交易所杠杆 L(人工设置)与资金分布;例:杠杆留在交易所默认(常见 10–20x,待核实)且永续所只占 20% 资金 → e ≈ 0.33,不利约 +6% 就进 L1。依据:pc:86;hft-risk:345;SDK:441–450 无杠杆字段;launch:67 只有人工步骤。修:pc 增加与杠杆无关的硬上限 `Σ|永续名义| ≤ margin_balance / e_min`(每个永续 venue)并重写 :86 论证;SDK 暴露每 inst 实际杠杆;可选 `RiskParams.max_perp_leverage`,超出 → ACCOUNT_CFG 不符。

### P2

3. 重试与重设目标规则不完整:`fail_until_ens` 不被闸门检查(:249 vs :183–199);每个 BBO 都可能 `ctx.target`,exec:525 替换旧目标清零 filled 并写 ExecDecision → 刷爆 journal;confirm 窗口 Confirmed 后 reset 导致设/清抖动(strat-lib:307、:181)。需写明只在 |Δq| 超带宽或原因变化时重设,复查用即时条件。

6. 每 venue 回到 L0 时有无事件不清(pc:234;SDK:497;hft-risk:407)。
7. L2 截止 30 s 内用 500 USDT/片做不完(hft-risk:411);默认 2x 下 +30% 只到 L2(L3 在 +33–36%,:592),门槛 ⑦ 测不到 L3。

11. 约 30 MiB 快照一次 `Model::snapshot` 写出(:537;SDK:123),超 advisor 每次 ≤ 1 ms 时间片(07:45 与 ctl-gateway 同线程)→ 需要按 group 分块的快照接口。
