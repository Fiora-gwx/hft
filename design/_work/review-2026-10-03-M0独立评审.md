# M0 修订后的独立评审(2026-10-03)

> 无上下文子代理的只读评审,只给了用户原始要求(`round8-decisions.md`),未给本轮简报与此前评审。下文为其结论摘要;主控已逐行核对 P0-1、P0-2、P0-3、P1-3、P1-4 的出处属实。处置待用户对 §4 的决定。

## 1. 结论

规格质量足以开工 M1(types、event、refdata、rt、journal、book)。M2(决策核心)开工前必须先修 3 个 P0 与 P1-1、P1-2、P1-3、P1-6 中涉及接口的部分(会改 SDK 视图/事件形状、ledger 数据模型、checkpoint 格式)。dev2 的资源数字与首个策略需求对不上;模拟账户与实盘共用热 sequencer 且 sim 回报优先级高于实盘 BBO,与"延迟优先"冲突。

## 2. 发现

### P0

- **P0-1 余额域只在 refdata/reconciler 存在**:ledger、SDK 视图、风控、sim 都按 venue 记现金。OKX 统一账户 / Bitget UTA 若现货与永续共用钱包,同一笔 USDT 会在两个 `VenueBook` 各记一份,策略按约 2 倍资金分配,第二腿余额不足被拒 → Broken → 裸腿。refdata 默认"未核实 = 各自独立"。B1 不检查第二腿可负担性。修法:ledger 按余额域记现金、SDK `PortfolioView` 按域汇总、sim 按域建钱包、未核实时拒绝同一账户同所两腿;B1 加第二腿可负担性检查。(`hft-refdata:64,382`、`hft-ledger:89-96`、`hft-strategy-sdk:320-330`、`venue-okx:165,196`、`hft-sim:249-253`)
- **P0-2 Broken 的 group 被排除在 L3 默认减仓与 `Kill{Account, flatten}` 之外**(`hft-exec:379` "且不处于 Broken 的 cell";`:384` engine_flatten 同一机制)。最危险的裸永续空单反而不减。修法:L3/flatten 对 Broken cell 至少做"只减永续腿、reduce-only、受 `max_reduce_notional` 约束"的减仓;runbook 写明。
- **P0-3 对冲腿在退化条件下必然 Broken,之后只能人工处理**:B1 两腿检查不含 #5(报价新鲜度/价格带)(`hft-risk:239`);对冲腿报价 > 500 ms 或滑点 > 50 bp 时 3 s 内 Broken;冷启动 30 s > `hedge_deadline_ms` 3 s;Broken 后只能 `/hedgefix`,夜间可能数小时。修法:链接 Open 前要求第二腿报价年龄 ≤ `hedge_quote_max_age_ms` 并把 #5 加入 B1;对冲腿超滑点改按 `rr_max_cross` 定价而不算失败;Broken 持续 `broken_auto_fix_ms` 后自动做一次带上限的平多出一腿(待决定)。

### P1

- **P1-1** Advice 按到达时刻判新鲜,重放/advisor 落后时旧建议被当新的。`EventRef::Advice` 增加 `basis_seq`/`basis_tsc`;watchtower 加 AdvisorLag 规则。
- **P1-2** Model 检查点格式三处不一致(SDK、hft-sequencer、hft-core);hft-core 按参数版本/refdata 版本/二进制 SHA 丢弃检查点 → 日常运维反复触发约 42 h 不开仓。检查点键只用 kind_id、Model 状态布局版本、schema.id、last_seq;统一命名;SDK 增加"预热数据作为 Input 注入"的通用通道。
- **P1-3** dev2 资源不自洽:advisor 预算 64 MiB 而首个策略约 1 MiB/group × 64;检查点上限 64 MiB 且两代合计 → 永远写不出;`max_instances` = 4 与 `sim_pool` = 4 冲突;`max_groups` 在 hft-exec 是总数、在 SDK 是每实例;cdex 重启会触发护栏停 hft,打断 14 天连续运行。
- **P1-4** 模拟账户与实盘共用热 sequencer:`rep-sim` 优先级 2 高于实盘 `bbo` 3;派发不分 Live/Sim;c8 核 1 同时承载 persist、advisor 镜像、sim-gw。
- **P1-5** 资金费差异无处置路径:`AdjustDelta` 只有 Position/Balance,严格闸门可能被一条 Funding Warn 永久卡住;Bitget `RateOnly` 每期都可能产生差异。
- **P1-6** portfolio-carry 负资金费时平仓成本门可能永不放行(平仓收益只算换仓机会,活跃集为空时为 0),组合会持续付负资金费。
- **P1-7** 解耦缺口:策略专项报表、策略 Note 码表没有 SDK 出口;`ManualOpen` 的 mode 语义写在引擎命令里;多个引擎 README 出现 `cdex`(违反 AGENTS 规则,checker 未覆盖小写)。
- **P1-8** pipeline 写了纯 Python 编码器,与"只有一份编码实现"矛盾;schema 导出命令与文件名两套。

### P2

`Tomb`/`MarginRow`/ledger Margin 行的字节数与字段和不符;`GROUP_NONE` 未定义而多处使用(ledger 又规定 group 0 = unassigned);`Ack` 命令悬空;`RecoverMismatch` 级别 P0/P1 不一;`SimAccountCfg` 在 refdata 与 hft-sim 两种形状;SDK 的 `AdviceHdr` 缺 `basis_seq`;Shadow cell 与 ledger 外来成交归属唯一性冲突;跨开机只重算部分 tsc;pipeline SetParams 是否需确认口径不一;Sim 账户 kill 两种写法;无 client id 成交 1 s 后转 ExternalFill、之后又被匹配导致一次多余的补腿往返。

## 3. 值得保留

单写者 + journal 即真相;传输错误 ≠ 业务失败;`HEDGE_LIMIT`;classify 唯一来源;启动闸门(UID、kill 自检、严格对账);MarginStress 三档;模拟 = 账户类型;解耦落在可机检结构(registry、deps.toml、CI 门槛);dev2 护栏 cdex 优先、fail-loud。
