# 00 · 目标、非目标与延迟预算

> 本章是设计证据与目标的来源;分段预算的数字以 [hft/docs/latency-budget.md §3](../docs/latency-budget.md) 为唯一归属,门槛 ⑩ 的判定以 [hft/docs/testing.md §8.2](../docs/testing.md) 为唯一归属,冲突处以 hft 为准。2026-10-03(M0-d)收包模型改为中断驱动后的预算重定记录在 §4.1;同日 M0-e 定下"硬线 = 验收下限、基准形态 = 目标"的关系与 ⑩ 的证据口径,记录在 §4.2;M0-f(R8-12)补的证据效度与退路也在 §4.2,规则只在 testing §8.2。

## 1. 目标

把现在的雏形(Rust 采集 + Python 执行,tick-to-trade 3–5 ms、链上腿 1.3 s、信号到双腿完成 2.5–3 s;各雏形的处置见 [01 §8](01-总体架构.md))重建为新的交易系统,首要服务 CEX-CEX 策略([07 §1](07-策略层.md))。目标按优先级:

1. **延迟**:p50 / p99 做到我们能控制的极限(下表)。高频交易里时间最重要;微秒级机制(忙等绑核、RAM journal + persist、帧模板、热备连接、conn-builder、BBO 独立连接与独立线程)是 core 设计,不因首个策略对延迟不敏感而降级。
2. **正确性**:任何传输错误不产生错误的仓位动作;不留裸腿(开仓前查第二腿,断腿有界自动处置,[09 §4.8](09-可观测性、风控与控制面.md));账本与交易所一致;昨天的日志今天重放逐字节一致。
3. **可扩展**:**新增或修改策略不改引擎**——策略包只依赖策略 SDK,装配处加一行注册,依赖方向与文档由机检保证([07 §2](07-策略层.md));新增交易所只加 venue 适配层与能力表;研究数据、可回放性、可靠性是设计内建而非事后补丁。

## 2. 非目标

- 不做通用交易平台、不对外提供服务;只服务自己的策略族(见 [07](07-策略层.md))。
- **不建历史回测系统评估策略**:回测一定不准(成交、队列、延迟、冲击、资金费与保证金的路径依赖都只能近似);策略用模拟账户(实时行情 + 模拟撮合,策略代码与实盘相同)观察与改进,正式实盘开始后同参数模拟与实盘并行校准([07 §9](07-策略层.md))。`replayer sim --ab` 只给同一段已录 journal 上两组参数的**差值**,默认关闭、报告首行强制标注"相对比较,不是收益估计,不得用于定仓"(R8-10)。不设小额实盘阶段:只有模拟盘与正式实盘(R8-9);正式实盘前有零成交冒烟与正式实例 Shadow 3–7 天(不开仓,[11 §5](11-实施路线图.md))。确定性回放只用于正确性验证与排障。
- 不做反向携带(空现货需要借币)。
- 不做同一交易所的现货 × 永续:一个账户在同一交易所只用一个市场(现货或永续),统一账户共用钱包的情形因此不建模([07 §1](07-策略层.md),2026-10-03 决定)。
- 不追求 L3 全深度重建与做市商级别的队列建模(除非 B 类策略证明需要,再对少数合约开)。
- 基准形态不做任何内核绕过(DPDK/AF_XDP/Onload-on-ENA),证据见 [03 §4](03-网络与传输层.md);裸金属 + Onload 是可选扩展,触发条件见 [03 §5](03-网络与传输层.md)。
- 不迁 colo,除非交易所迁出 AWS 或提供交叉连接([02 §3](02-硬件与托管方案.md))。
- 不把任何开源交易框架放进实盘依赖树。

## 3. 延迟的定义(全系统统一)

每个事件携带五个时间点,每笔订单再加三个;时间点与分段的名称和语义以 [latency-budget §1–§2](../docs/latency-budget.md) 为准(设计理由见 [09 §1](09-可观测性、风控与控制面.md)):

```
ex_ts(交易所事件时间) → ex_send(交易所发送,若有) → hw_rx(网卡硬件戳) → rx_tsc(用户态读完) → proc_tsc(sequencer 取出)
→ decided_tsc(策略/风控/OMS 完成) → sent_tsc(write 返回) → [hw_tx 无,ENA 不支持] → ack(回执到达 hw_rx)
另:sw_rx(内核软件接收戳)常态记录,把 kernel_rx 拆成 nic_to_kernel 与 kernel_to_user 两段诊断(不作门槛)
```

- **tick-to-trade(主机内)** = `sent_tsc − hw_rx`。所有"主机内"目标都指这个。
- **rep_to_order(回报 → 下一单)** = 由某条回报(`OrderEvent` 帧:Ack、Fill、Cancel 等)触发的下一笔订单的 `sent_tsc` − 该回报帧的 `hw_rx`(计算同 `tick_to_trade`)。它走的路径与对冲相同(gw 解码 → rep 环 → sequencer → out 环 → gw 发送),但不要求真的成交:`latency-probe` 的 `quote` 模式 Ack 后在同一事件内撤单就产生一个样本,所以能在主网行情负载下大量采样。`LatencySample` 按触发事件的 kind 区分它与 `tick_to_trade`;撤单与改单同样由 hft-oms 合成样本,`LatencySample.action`(New / Cancel / Amend)区分,`order_rtt` 只统计新单,`rep_to_order` 含三种 action(字段归 [hft-event](../crates/hft-event/README.md))。
- **hedge_host(对冲主机内)** = 第二腿 `sent_tsc` − 触发它的第一腿成交帧的 `hw_rx`(按 `kernel_rx + (sent_tsc − rx_tsc)` 计算);它是 `rep_to_order` 的子集(只取 LegLink 第二腿,`link_role = Second`,不含 SecondRetry),包含成交回报在 gw 与回报环里的等待,`leg_gap` 看不到这一段。
- **跨时钟域换算**:含 PHC 端点的分段(`kernel_rx` 等)要把 `hw_rx`(PHC)换算到 TSC。housekeeping 每 1 000 ms 写一条 `ClockStatus`(Meta,含 `(tsc, phc, calib_err_ns)`),每个样本按前后两条校准对线性插值并得到误差界;误差界 > 1 µs 的样本计入 `unsynced_cal`、不进分位数;HW 时间戳不可用时以 `sw_rx`(REALTIME)为锚。规则归 [latency-budget](../docs/latency-budget.md)。
- **端到端 tick-to-ack** = `ack.hw_rx − trigger.hw_rx`,包含网络与交易所,用于业务评估。
- **行情单向** = `hw_rx − ex_ts`(需 PHC 时钟,误差 < 40 µs;交易所时间戳 ms 级,只能看大样本分布)。
- 所有分位数按 (venue, 事件类型, 分段) 分组报告;**不同数据集不混算**;HW 与 SW 时间戳的样本分开统计。

### 4.1 收包改为中断驱动后的预算重定(2026-10-03,M0-d)

**原来的数字**:基准形态主机内 `tick_to_trade` p50 ≤ 20 µs、p99 ≤ 60 µs、p99.9 ≤ 200 µs(硬门槛),其中"网卡 → 用户态" p50 1–4 µs、p99 < 10 µs。这一段取自 [03 §2](03-网络与传输层.md) 分段成本表的"忙轮询"一列(NIC → socket 队列 1–3 µs),而且整张表按 c7i.metal 估算。

**为什么改**(五路评审 V5 P0-1、P1-3,V4 P1-5;[13 §17](13-设计评审与优化.md)):

1. 规格里同时存在两种收包模型:hft-net 与 T12 写"IRQ/NAPI 在 hk 核、热线程只做非阻塞 `recvmsg`、`SO_BUSY_POLL` 默认不设",deploy 却全局设 `busy_poll/busy_read = 25`、`napi_defer_hard_irqs = 2`、`gro_flush_timeout = 200000`,本章原先的预算又取自忙轮询列。新 socket 默认继承 `busy_read`,热线程每次空读都会替同一队列上的全部 socket(包括同机 sim 的行情)做 NAPI 轮询;一时没人轮询时,包最多等 200 µs。
2. hk 核同时承担全部 IRQ、housekeeping、persist、段预创建(`MAP_POPULATE` 50–100 ms)与系统服务,软中断溢出到 ksoftirqd 后会出现毫秒级 `kernel_rx` 尾部。
3. 目标是 Graviton 虚拟机,不是 c7i.metal。

**决定**:只保留**中断驱动**一种模型——`busy_poll`/`busy_read` = 0,ENI-B 的 `napi_defer_hard_irqs = 0`、`gro_flush_timeout = 0`,conn-builder 建连时显式 `SO_BUSY_POLL = 0`,hostprobe 硬校验;ENI-B 全部队列的 IRQ 钉在一个**专用 IRQ 核**(升级主机类的核 1,不放任何线程),ENI-A 在核 0;sim 用独立的 ENI-C,IRQ 钉在 sim 的核上。预算按中断驱动列重定(分配,待 M1.5 实测):

| 分段 | p50 | p99 |
|---|---|---|
| `kernel_rx` | ≤ 8 µs | ≤ 20 µs |
| `ingest`(bookTicker) | ≤ 3 µs | ≤ 10 µs |
| `ingest`(depth) | ≤ 4 µs | ≤ 12 µs |
| `decide` | ≤ 5 µs | ≤ 15 µs |
| `egress` | ≤ 5 µs | ≤ 15 µs |
| **`tick_to_trade`** | **≤ 22 µs** | **≤ 75 µs**(p99.9 只记录) |
| `hedge_host`(新) | ≤ 25 µs | ≤ 80 µs |
| `feed_host` | ≤ 12 µs | — |
| `leg_gap` | ≤ 20 µs(不变) | — |

85% 规则校核(各段 p99 之和不超过总 p99 的 85%):20 + 10 + 15 + 15 = 60 ≤ 0.85 × 75 = 63.75。验收下限仍是 p50 ≤ 30 µs、p99 ≤ 100 µs。

同时定下的验收口径中,**三项已被 §4.2 取代**(只作记录):"p50、p99 是硬门槛"(现为硬线 = 验收下限、基准形态 = 目标);"`hedge_host` 是门槛 ⑩ 的硬项之一"(现只记录,对冲路径的硬线由 `rep_to_order` 承担);"同机干扰按 7 天内每小时交替开/关 sim、取配对比值中位数判定劣化 ≤ 5%"(现按块配对、看 bootstrap 置信区间上界,见 §4.2 与 testing §8.2)。仍有效的两项:p99.9 只记录(Binance 深度每 100 ms 集中推送、周期关键帧快照下,p99.9 主要反映固定节拍突发,不适合作硬门槛);`sw_rx` 改为常态记录(追加进 `MarketHdr` 与 `LatencySample`)。

与收包模型一起改的结构(各自唯一归属在 hft):sequencer 的 md 改为逐条处理、每条之后查看 ctl/rep/bbo 环头,BBO 在 sequencer 侧最多等正在应用的那一条 md 消息([hft-sequencer](../crates/hft-sequencer/README.md));同一 venue 的 feed 拆成 `feed-bbo:<venue>` 与 `feed-md:<venue>` 两个任务,REST 快照移到 warm 任务 `snap-fetch`([hft-venue](../crates/hft-venue/README.md));gw 每圈 poll 用户流、每解一帧回报 `drain_out` 一次。这些改动连同 IRQ 独占核让升级主机需要更多核,所以主机类改为默认候选 `c32`、下限候选 `c16`([02 §2.2](02-硬件与托管方案.md);M0-e 起 `c16` 只在 M3 末探针达标且启用 `epoll_pwait(0)` 时保留)。

### 4.2 硬线与目标、门槛 ⑩ 的证据(2026-10-03,M0-e)

**为什么改**(第四轮评审 W5 N-P1-4、N-P1-5、N-P1-6、P2-8,W3 P1-47;R8-11):

1. 规格里同时写着两种 ⑩:本章与 [11 §4](11-实施路线图.md) 写"22 / 75 是硬门槛",testing 写"30 / 100 是硬线、两者之间 Admin 签字"。用规格自己的数字推算,`c32` 上 p50 22 µs 只在中断路径落在证据区间低端时闭合,M1.5 的简化切片又定不了档,把 22 / 75 当硬门槛等于把一个未经实测的分配当成验收条件。
2. `kernel_rx` 跨 PHC/TSC 换算,而校准对原来每 60 s 才记一条、阶梯取值;TSC 与受控 PHC 只要差 0.1–1 ppm,误差就有 6–60 µs,与 8 / 20 µs 的预算同量级。
3. 探针按时间抽样(每 inst 每秒至多一单),低估突发时段的尾部;`hedge_host` 只能在测试网行情(轻负载)上测,还要另占 ≥ 7 天;同机干扰在 `hedge_host` 的样本量下,"≤ 5%"落在统计噪声里;每小时交替与偶数小时的资金费结算混在一起,配对消不掉。

**决定**(数字的唯一归属是 [latency-budget §3](../docs/latency-budget.md),判定的唯一归属是 [testing §8.2](../docs/testing.md)):

| 项 | 硬线 = 验收下限 | 目标 = 基准形态 |
|---|---|---|
| `tick_to_trade` | p50 ≤ 30 µs、p99 ≤ 100 µs | p50 ≤ 22 µs、p99 ≤ 75 µs |
| `rep_to_order`(对冲路径) | p50 ≤ 35 µs、p99 ≤ 110 µs(M3 末探针后可重定) | p50 ≤ 25 µs、p99 ≤ 80 µs |
| `hedge_host` | 只记录(`rep_to_order` 的子集) | p50 ≤ 25 µs、p99 ≤ 80 µs |

- **三档判定**:不劣于目标 → 通过;落在目标与硬线之间 → 通过,差距与原因写进验收记录并由 Admin 签字;劣于硬线 → 不通过。p99.9 只记录。凡是写"基准形态是硬门槛"的地方都改为链接 testing。目标保留的作用是指方向:分配、基准与参考机回归都按目标做,差距要有解释。
- **时钟**:`ClockStatus` 每 1 000 ms 一条,逐样本线性插值并给误差界,误差界 > 1 µs 的样本计入 `unsynced_cal`、不进分位数;HW 戳不可用时以 `sw_rx` 为锚;⑩ 的报告附误差分布(§3)。
- **证据**:`kernel_rx`、`ingest`、`feed_host` 从 seq journal 对**每条带 `MarketHdr` 的行情记录**(含 TopN 快照;记录集合归 hft-telemetry)离线计算(记录头 tsc + `MarketHdr` 的 hw/sw/rx 时间戳;hft-telemetry 的 `event_weighted()` 与命令 `replayer latency`),按事件加权、热路径零成本;探针样本只用于订单类分段。`rep_to_order` 由 `quote` 模式在主网行情负载下产生(Ack 后的撤单也产生样本,§3);`pair` 模式只作小样本确认(M6 dev2 联调窗口,或 M7 任意 ≥ 1 天的测试网行情时段,只记录)。所以 ⑩ **只有一个 7 天主网行情窗口**,不再另取 ≥ 7 天 `feed_env = testnet` 窗口。`pair_period_ms` 默认 10 000(约 8,640 个样本/天)。
- **同机干扰**:按块开/关 sim、按块配对,判定看 p99 比值(开 / 关)的 bootstrap 置信区间上界;样本量不足的组只记录(含 `hedge_host`)。块长、阈值与样本量下限只在 testing §8.2。
- **效度与退路**(M0-f,R8-12;第五轮评审 X5 L-P1-1、L-P1-2、L-P2-10,X2 P1-5;规则全部归 testing §8.2):
  1. 突发时段:`MarketHdr.rx_empty_gap_ns`(本连接上次确认接收队列为空到本次读到这批数据的间隔)给出 `kernel_rx` 的上界,⑩ 报告并列 `kernel_rx` 的上下界;M1.5 与 M3 末探针按"突发 / 平静"分层抽样。
  2. HW RX 时间戳不可用,或 `unsynced_cal` 占比偏高(阈值待标定)时,⑩ 改用 SW 锚数据集判定,数值门槛不变,报告注明"不含网卡到软中断一段"。
  3. 同机干扰:窗口前先做 1–2 天 A/A(两段都关 sim)估计区间宽度;开关顺序按资金费块分层配平;区间过宽时延长窗口,不判失败。

**代价与取舍**:硬线放宽 8 / 25 µs 不等于降低目标——没有 M1.5 与 M3 末探针的 Graviton 实测之前,22 / 75 只是分配;先承认可接受的下限,再用签字把"为什么没到目标"留成记录,比让一个未实测的数字卡住正式实盘更诚实。`rep_to_order` 的硬线比 `tick_to_trade` 宽 5 / 10 µs,留给回报路径上 gw 的回报解码与 rep 环等待(R8-11 采纳评审建议的 35 / 110,M3 末探针实测后可重定)。

## 6. 验收方法

- 每个目标都有对应的直方图指标与每日报表([09 §2](09-可观测性、风控与控制面.md))。
- **延迟证据提前**:M1.5 延迟探针在按需租用的 `c8g.4xlarge` 上跑纵切片(hft-net + 一个 venue 的 BBO feed + 简化 sequencer + gw 测试网下单),HW 与 SW 时间戳分开出直方图,另测"压舱"深度连接下的 `nic_to_kernel`、IRQ 核空闲与保持唤醒的 A/B、`calib_err_ns` 等收包与时钟事实,结论写 Agent Note;M3 末在同一型号上跑满订阅探针(另在 `c8g.8xlarge` 上按 `c32` 计划跑一次)选定主机类;从 M1.5 起每个里程碑结束时在同型租用实例上跑 `bench-gate --reference`(相对回归 + 单 crate 上限),不是 CI([11 §3.1、§3.2](11-实施路线图.md))。
- **样本量**:组合携带是分钟级调仓,凑不够每组 1,000(p99)样本;所以 registry 里有一个只能绑定非正式账户的 `latency-probe` 策略(`StrategyDesc.non_prod_only = true`):`quote` 模式每个 (venue, inst) 在 `Bbo` 触发时至多每 `probe_period_ms`(1 000)挂一张离对手价 `far_bp`(300 bp)的最小名义 PostOnly 单、Ack 后在同一事件内撤单,约 8.6 万个 `tick_to_trade` 样本与同量级的 `rep_to_order` 样本/天/inst(主网行情负载下);`pair` 模式每 `pair_period_ms`(10 000)在两所测试网各做一次最小名义的穿价 IOC + LegLink 第二腿并在 `pair_flat_ms`(5 000)内平掉,约 8,640 个 `hedge_host`/`leg_gap` 样本/天,只作小样本确认;`target` 模式走 `TargetIntent` → hft-exec 切片路径。`kernel_rx`、`ingest`、`feed_host` 不靠探针,从 seq journal 按事件加权离线计算(§4.2)。默认 `enabled = false`,参数与样本口径归 [strategies/latency-probe](../strategies/latency-probe/README.md)。
- 基准形态的延迟验收(门槛 ⑩,在统一升级后的主机上、prod 与 sim 两个实例同机运行时进行:主网实时行情 + 交易所测试网/模拟盘下单回路测主机内分段;`dev2`/`c4` 只记录直方图,无延迟验收):一个连续 7 天的主网行情窗口内,各硬项不劣于硬线(落在目标与硬线之间需 Admin 签字),同机干扰按 bootstrap 置信区间上界判定,且回放决定性测试通过;不再另取测试网行情窗口(§4.2)。判定的唯一归属是 [testing §8.2](../docs/testing.md);正式实盘前的上线门槛(含测试网/模拟盘联调、模拟账户运行时长与压力用例,不含小额实盘)的唯一定义在 [hft/docs/testing.md §8](../docs/testing.md)。
- 可选的 wire 级 mock 交易所每夜全链路回环([10 §5](10-语言分工与代码组织.md))。
- 交易所侧数字(单向、RTT)每周复测并存档,AZ/spine 漂移时触发迁移评估。
