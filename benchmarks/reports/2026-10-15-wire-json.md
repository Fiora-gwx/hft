# Wire JSON 字段投影测量

本报告为共享 Windows x86_64 开发机诊断，不是 aarch64 参考机验收。基线 `408b496c`；同一 HistBench 驱动分别运行基线与投影实现。开发配置 `opt-level=3, debug=0`，保留溢出检查；每项预热 5,000 次、采样 50,000 次，不绑核，Windows Instant 计时。其他 agent 同机运行，因此不得据此断言 p99 改善。未访问 c8g 主机。

测量从生产 peek/decode_md 入口到返回，包含 fixed-point 转换、refdata 查找、归一化与预分配 sink 写入，不包含 socket/TLS、环交接或 sequencer。实际捕获 BBO 与既有合成用例分别报告。原始输出见 [JSON](2026-10-15-wire-json.json)。

BBO 中位耗时下降，但 Bitget BBO 的 p99 上升。未改写的 Binance trade/depth 解码还有波动或小幅回退，不能把本报告当作全类型加速承诺。局部比较与代码审查定位到通用字段匹配、重复遍历和 Arr 数组逐项初始化；数组改为常量初始化。私有报告与账户仍使用已有严格借用解析器，通道/事件分派可投影。账户 warm 路径不属于无分配热路径。

每次纯解码调用的系统调用数为 0（代码路径与分配测试审计，非内核 trace 测量）。Linux socket syscalls/message、硬件采样 profile、aarch64 p50/p99、NIC 到 BBO 的端到端结果需在独立获准的参考运行补齐。
