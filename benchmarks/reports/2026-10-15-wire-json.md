# Wire JSON 字段投影测量

本报告为共享 Windows x86_64 开发机诊断，不是 aarch64 参考机验收。基线 `408b496c`；同一 HistBench 驱动分别运行基线与投影实现。开发配置 `opt-level=3, debug=0`，保留溢出检查；每项预热 5,000 次、采样 50,000 次，不绑核，有序 TSC 计时，频率取 nominal 或一次校准。其他 agent 同机运行，因此不得据此断言 p99 改善。未访问 c8g 主机。

测量从生产 peek/decode_md 入口到返回，包含 fixed-point 转换、refdata 查找、归一化与预分配 sink 写入，不包含 socket/TLS、环交接或 sequencer。实际捕获 BBO 与既有合成用例分别报告。原始输出见 [JSON](2026-10-15-wire-json.json)。

BBO 中位耗时下降，但 Bitget BBO 的 p99 上升。未改写的 Binance trade/depth 解码还有波动或小幅回退，不能把本报告当作全类型加速承诺。局部比较与代码审查定位到通用字段匹配、重复遍历和 Arr 数组逐项初始化；数组改为常量初始化。私有报告与账户仍使用已有严格借用解析器，通道/事件分派可投影。账户 warm 路径不属于无分配热路径。

每次纯解码调用的系统调用数为 0（代码路径与分配测试审计，非内核 trace 测量）。Linux socket syscalls/message、硬件采样 profile、aarch64 p50/p99、NIC 到 BBO 的端到端结果需在独立获准的参考运行补齐。

## 私有报告与账户的既有 Criterion 基准

同一开发配置运行原有 reports harness，默认 100 个样本。下表是 Criterion 估计值（非逐消息 p50/p99）。基准包含 fresh/duplicate 路径与 warm 账户全量解码；不得把 warm 解码称为热路径。

| 调用 | before | after |
|---|---:|---:|
| `bench_decode_otu/own` | 2.7498 µs | 5.5094 µs |
| `bench_decode_otu/own-duplicate` | 1.1639 µs | 2.031 µs |
| `bench_decode_otu/external` | 5.3625 µs | 5.8454 µs |
| `bench_decode_otu/external-duplicate` | 2.1614 µs | 1.9048 µs |
| `bench_skip_event_usdm/listed` | 23.833 ns | 23.023 ns |

私有报告没有可确认的收益，多项回退。连未修改的 Bitget encode 也从 79 ns 变为 182 ns，显示同机干扰足以改变比较；需要在独占参考核心复测后决定是否扩展字段投影到订单/账户体。这里不隐藏回退，也不把均值冒充 p99。
